# POT1 saturation genome editing

> ### Not for clinical use
>
> These functional scores are research data from a study that has not yet completed peer
> review. **They must not be used for clinical diagnosis, variant interpretation, patient
> management, or any other clinical purpose.** Classification of a variant for clinical
> purposes requires the full evidence framework, of which an experimental functional assay
> is one component among several.

Analysis pipeline for a saturation genome editing (SGE) screen of *POT1*. It
takes raw per-library read counts and produces a functional score, a statistical
classification and a full annotation for every variant assayed.

The repository is self-contained: the input data is included, no paths need
editing, and the whole analysis runs in about four minutes.

```bash
Rscript install_dependencies.R   # once
Rscript run_pipeline.R
```

Output appears in `results/`.

---

## What the screen measures

Variants are introduced into the endogenous *POT1* locus across nineteen
targeted regions, and the cell population is sampled at five timepoints —
days 4, 7, 10, 14 and 21 — in triplicate. A variant that impairs POT1 function
changes how quickly cells carrying it drop out of, or accumulate in, the
population. The analysis measures that rate of change for each variant and asks
whether it differs from the variants expected to be neutral.

The headline quantity, the **functional score**, is the slope of log abundance
against time, estimated jointly across all five timepoints. Negative scores mean
depletion, positive scores enrichment.

## Running it

```bash
Rscript run_pipeline.R                 # the whole pipeline
Rscript run_pipeline.R --stage 2       # stop after counting and filtering
Rscript run_pipeline.R --qc-plots      # also write per-library QC plots
```

Requires R 4.4 or later with DESeq2, DEGreport, mclust, openxlsx and the
tidyverse; `install_dependencies.R` installs them. Every run records its exact
package versions in `results/logs/sessionInfo.txt`.

## Layout

```
config.R                  all paths, the library manifest, analysis constants
run_pipeline.R            entry point
install_dependencies.R    one-off dependency install
R/01_counts.R             read counts into one matrix per library
R/02_annotate.R           attach library design and VEP annotation, filter
R/03_deseq.R              DESeq2 models, normalisation, median centring
R/04_combine.R            combine libraries into one variant-level table
R/05_classify.R           expand annotation, ClinVar, depletion classes
R/06_qc_plots.R           optional per-library QC plots
R/07_final_table.R        external annotation and final table layout
data/                     all inputs — see data/README.md
qc_plots/                 per-library quality-control plots
supplementary_data/        the variant tables, regenerated by the pipeline
published_files/          the variant tables exactly as submitted with the paper
molecular_dynamics/       MD simulations of POT1 and six missense variants
results/                  output, created on first run
```

`config.R` is the only place a path, a library or a constant is defined. If you
want to understand how the analysis is parameterised, read that file first.

`published_files/` holds the same two tables **exactly as submitted with the

## How the analysis works

### 1. Counts

Eighteen libraries, fifteen samples each (five timepoints × three replicates),
plus a plasmid library where one was sequenced. Three reading modes, recorded as
`plasmid_mode` in the manifest in `config.R`: a single pre-merged plasmid file,
a plasmid sequenced across two lanes with the SGE counts split the same way and
summed, or no plasmid library at all.

Timepoint and replicate are parsed from each filename and the columns assembled
by name, with a check that all fifteen combinations are present.

### 2. Library design, annotation and filtering

Counts are joined to the VaLiAnT design metafile on oligo id. Two filters then
apply, in order: oligos with fewer than ten reads summed across the fifteen SGE
samples are dropped, then variants falling in constant, non-targeted regions are
dropped. The VEP annotation is joined last, restricted to the POT1 MANE Select
transcript `ENST00000357628.8`.

Per-library counts for every step are written to `results/filter_summary.csv`.

### 3. Modelling

Each library is modelled separately with DESeq2.

**Normalisation uses the neutral variants only.** Size factors are estimated
from the synonymous and intronic variants and then forced onto the full model.
Estimating them from everything would treat a real, genome-wide depletion as a
library-size effect and normalise the signal away.

**Two models are fitted** against those same size factors: a discrete one with
day 4 as the reference level, giving log fold changes for D4→D7, D10, D14 and
D21; and a continuous one with condition set to days elapsed since day 4
(0, 3, 6, 10, 17), whose single slope is the functional score.

**Log fold changes are then centred** on the median of the neutral set, and the
p-values recomputed from the centred values. Centring shifts an estimate without
changing its standard error, so the standard errors carry through unchanged.

No shrinkage is applied to the log fold changes. Shrinkage estimators such as
apeglm are the sensible default for RNA-seq, where most genes are unchanged and
estimates are noisy; here the effects of interest are real and shrinkage would
pull them toward zero.

Three libraries lost a replicate to quality control. The exclusions are declared
once, in the `drop_reps` column of the manifest, and the experimental designs
are generated from it.

#### A note on the dispersion trend

DESeq2 fits a parametric dispersion trend where it can and falls back to a local
regression where it cannot. That choice is made by an iterative Gamma GLM
started at a fixed point, `c(0.1, 1)`, which stops with an error if a
coefficient goes non-positive along the way; DESeq2 then silently substitutes
the local fit.

For a library whose asymptotic dispersion is near zero, the default start
overshoots and the fit fails even though a perfectly good solution exists — one
that is reached from several other starting values on the same data. The
consequence is that which model gets fitted can turn on differences of around
1e-9 in the inputs, which is to say on compiled code and hardware rather than on
the data.

`fit_dispersion_trend()` in `R/03_deseq.R` therefore tries the parametric fit
from DESeq2's own starting value first, then from progressively smaller
asymptotic dispersions, and falls back to a local regression only if none
converge. The model and DESeq2's convergence criterion are untouched; only the
starting value changes. The fallback remains automatic and decided by the data —
nothing is fixed per library — but it no longer depends on the machine. Eight of
the eighteen libraries fit parametrically under this rule and ten fall back.

### 4. Combining libraries

Fifteen of the eighteen libraries contribute. Where a targeton was covered by
both guide libraries only one was carried forward, so the only variants measured
twice are those in the overlap of the tiled targeton pairs, 3_1/3_2 and 9_1/9_2.
Those pairs are combined by inverse-variance weighting; everything else passes
through unchanged.

Variants are reduced to one row per mutant sequence before the
Benjamini–Hochberg correction, so each independent observation is counted once.
A variant is called **depleted** or **enriched** at FDR < 0.01 on the continuous
model, and **unchanged** otherwise.

### 5. Annotation and depletion classes

Statistics are expanded back onto every annotated oligo, and ClinVar is joined
on HGVSc. The depleted variants are then split into **strong** and **weak** by a
two-component Gaussian mixture on the D4→D21 against D4→D7 log fold changes
(mclust, ellipsoidal equal-volume covariance), separating variants that drop out
early from those that drop out slowly. The seed is fixed in `config.R`.

Two flags are added: variants within a 5 bp primer-binding window, where read
counts may be distorted, and variants falling in a PAM-edited codon.

### 6. External annotation and final tables

SpliceAI scores, GRCh38-normalised coordinates, EVE and CADD scores, and FoldX
ddG predictions are joined on, the counts for excluded replicates are blanked so
the reported values show only what was modelled, targeton numbering is converted
to exon numbering, and the columns are selected and renamed. See
`data/README.md` for what each external source is.

## Two conventions worth knowing

**Row order.** Rows are ordered by mutator — SNVs first, then the order used
throughout — then by descending genomic position, then by oligo id. The last key
is a tie-break with no meaning beyond making the output identical from run to
run and machine to machine.

**Choosing a representative row.** Eleven coding changes are reachable by two
different mutant sequences: eight are pairs of adjacent single-base deletions
that produce the same sequence, and three are the PAM-edited and unedited forms
of the same SNV in the 3_1/3_2 overlap. `selection_order()` in
`R/07_final_table.R` makes the choice explicit — prefer the SNV mutator, then
the higher position, then the measurement combined across both tiled targetons,
then oligo id — rather than letting it fall out of row order. Preferring the SNV
is what keeps a variant reachable as a plain SNV reported as one, rather than as
a recoded or deleted codon.

## Scope

Nineteen targetons were designed; targeton 7 has a count frame but was not
assayed, and neither it nor targeton 0 appears in the manifest.

Of the eighteen sequenced libraries, fifteen feed the variant table, for the
reason given in step 4 above. The other three are still modelled, so their
quality-control output is available in `results/per_library/`.

Figure code is not included here.

## Molecular dynamics simulations

`molecular_dynamics/` presents all-atom simulations of wild-type POT1 and six
clinically observed missense variants bound to telomeric single-stranded DNA,
asking whether the SGE functional classes have a visible structural correlate.
These are exploratory, are independent of the pipeline above and share no code
with it, and no result in the paper depends on them.

`molecular_dynamics/README.md` presents the simulations and sets out what can
and cannot be read from them, with a further-work section.
`protein_dynamics.html` is the same material as a standalone page.
