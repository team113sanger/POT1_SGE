# Input data

Everything the pipeline reads. All files are gzipped and are read directly —
there is no decompression step. Total size is about 17 MB.

```
data/
├── counts/           read counts per library, per sample
├── plasmid/          plasmid library read counts
├── library_design/   VaLiAnT design metafiles
├── vep/              Ensembl VEP annotation
├── external/         annotation from outside this experiment
└── metadata/         column documentation for the output workbooks
```

---

## `counts/` — saturation genome editing read counts

One directory per library, named for the library (`E2_SGA` is targeton 2 against
guide library A). Produced by [pycroquet](https://github.com/cancerit/pycroquet),
which counts reads matching each designed oligo.

Filenames encode the sample: `2_a_D4_rep_1.query_to_library_counts.tsv.gz` is
targeton 2, guide library A, day 4, replicate 1. Libraries sequenced over two
lanes have two files per sample, distinguished by a run identifier
(`..._rep_1__44030_1_39` and `..._rep_1__44030_2_39`); the pipeline sums them.

Each file has two comment lines, then a header, then one row per oligo. The
pipeline uses the oligo id and the count column; the other columns describe the
oligo and are carried for reference.

## `plasmid/` — plasmid library read counts

Read counts for the plasmid pools, before transfection. These measure how evenly
each oligo was represented in the library as built, independent of any effect on
cell fitness, and are reported alongside the SGE counts for quality control.
They do not enter the statistical model.

- `Exon_<n>_<guide>_merged.query_to_library_counts.tsv.gz` — one pre-merged file
- `<n><guide>_lib__44030_<lane>_<id>.query_to_library_counts.tsv.gz` — two lanes,
  summed by the pipeline
- `pot1_exon_3_1_a_lib.counts.tsv.gz` and `POT1_14_B_PLASMID_LIB.lib_counts.tsv.gz`
  — targetons 3_1a and 14b, sequenced separately and in a different format, so
  they are joined at the end of the pipeline rather than at the start

## `library_design/` — VaLiAnT metafiles

One CSV per library, from [VaLiAnT](https://github.com/cancerit/VaLiAnT), the
tool that designed the variant library. Each row is a designed oligo and records
the genomic position, the reference and mutant bases, the mutagenesis rule that
produced it (`mutator`), the mutant sequence (`mseq`), whether the variant falls
in a PAM-edited codon, and whether it falls in a constant, non-targeted region.

The pipeline joins counts to this file on oligo id, so an oligo that was counted
but is not in the design is dropped.

Filenames follow the targeton coordinates:
`chr7_<start>_<end>_minus_sgRNA_w<targeton>_<guide>_meta.csv.gz`. `config.R`
builds these names from the manifest, which is why the coordinates appear there.

## `vep/` — Ensembl VEP annotation

One TSV per library: the VaLiAnT variants run through Ensembl VEP, giving
consequence, HGVS nomenclature, protein position, SIFT and PolyPhen scores,
gnomAD allele frequencies and existing variant identifiers.

VEP reports every overlapping transcript; the pipeline keeps only the POT1 MANE
Select transcript `ENST00000357628.8`. Each file carries 92 lines of `##`
metadata before the header, recording the VEP and cache versions used.

## `external/` — annotation from outside this experiment

These cannot be derived from the read counts. Each is a fixed snapshot shipped
with the repository, so the annotation does not shift underneath the analysis.

| file | what it is |
|---|---|
| `clinvar_pot1_all_20240312.txt.gz` | all ClinVar records for POT1, downloaded 12 March 2024 |
| `clinvar_pot1_onestar_20240312.txt.gz` | the same query restricted to a review status of one star or better |
| `spliceai_fixed_coords.csv.gz` | SpliceAI delta scores and positions, plus GRCh38-normalised `pos`/`ref`/`alt`, keyed on mutant sequence and oligo id |
| `eve_cadd_vep.csv.gz` | EVE and CADD scores, from a VEP run with those plugins, keyed on HGVSc |
| `ddG_mutfunc.csv.gz` | FoldX predicted folding free-energy changes for POT1 missense substitutions, keyed on UniProt residue position |

One variant has no entry in `spliceai_fixed_coords.csv.gz`: an indel that also
carries a PAM edit, so its GRCh38 coordinates are ambiguous. It is therefore
absent from the final tables. The pipeline asserts that it is the only row lost
at that join, so a future annotation file that silently dropped other variants
would stop the run rather than pass unnoticed.

## `metadata/` — output workbook documentation

`supp_data_<n>_notes.csv` documents every column of the corresponding output
workbook, and `supp_data_<n>_titles.txt` holds its title lines. These are
editorial text, written by hand, not generated by the pipeline. Edit them here
if a column description needs to change.
